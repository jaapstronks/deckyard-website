Deckyard is a presentation platform: you make decks in it, present them, publish
them to the web and work on them with colleagues. That part is not new. What is
new is that the source code is now public on GitHub under an MIT licence, so you
can read every line, run the whole thing on your own server, and change it if it
does not do what you need.

## This is not a waitlist for an idea

The order matters here. Deckyard was built because we needed it, used in real
work for months, and only then opened up. Everything on the site is describing
software that exists: 38 slide types, real-time collaboration, live polls and
Q&A, publishing and embedding, export to PDF and PowerPoint and self-contained
HTML.

So this post is not a promise about a roadmap. It is a pointer at a repository.

## Why open, and why now

Presentations are where organisations say what they think. That content ends up
sitting in someone else's cloud, in a format only their application can open, on
infrastructure under someone else's jurisdiction. For a school, a city council
or a public broadcaster that is a strange place for your own words to live.

Opening the source does not fix that on its own, but it removes the part that
cannot be fixed later: you can now run the thing yourself, and nobody can take
that away from you.

## What you can do today

Three doors, in increasing order of commitment. The sandbox is a full Deckyard
in your browser with no install and no account. The Docker Compose file gets you
a real instance on your own server in an afternoon. The repository is there to
read, star, file issues against, or fork.

## What is next

More writing, mostly. There are decisions inside Deckyard that are worth
explaining properly - why a slide is a record instead of a canvas, why the brand
lives in a theme rather than in the deck, what "GDPR-native" means when you say
it out loud instead of putting it on a badge. Those are the next few posts.
